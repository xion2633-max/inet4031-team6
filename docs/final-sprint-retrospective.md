# Final Sprint Retrospective

INET 4031 - Team 6  
Networking & Cloud Infrastructure

## What Went Well

Our group made good progress getting organized for the final sprint. We established a GitHub project board to track the success criteria and divided up the documentation tasks. We also verified that our Kubernetes environment was accessible and that the existing services were running. Having our previous work in the repository made it easier to continue without starting over.

Using branches and pull requests helped us keep changes organized. Team members could work on different files, review each other's work, and merge changes into the main branch after approval.

## Challenges We Faced

One challenge was making sure everyone had access to the development environment. Since we were using the university's shared Linux server, we needed to connect through the VPN and SSH before working with Kubernetes. Some of us also had to configure our Kubernetes context before commands would work correctly.

Another challenge was coordinating tasks while different parts of the project were still being prepared. We had to communicate about which files were already being handled so we wouldn't duplicate work.

## What We Learned

This sprint helped us better understand how Kubernetes, networking, GitHub, and documentation fit together in an infrastructure project. We practiced checking cluster status, inspecting deployments, and verifying that services were available.

We also learned why version control matters when multiple people are working on the same project. Using separate branches and pull requests makes it easier to review changes and avoid interfering with other team members.

## What We Would Improve

If we were doing another sprint, we would assign tasks earlier and keep the GitHub project board updated as work progresses. This would make it easier for everyone to know what they should be working on.

We would also make sure everyone verifies their environment access early so less time is spent troubleshooting connections during the project.

## Final Results

The team has verified the existing Kubernetes environment, organized the success criteria in GitHub, and started completing the required documentation. The final implementation, performance testing, and resilience testing are still being completed.
